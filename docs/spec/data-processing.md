# 数据处理规格

## 数据集划分

- 数据处理页左侧工具名称为“数据集划分”。
- 数据集划分支持 Labelme 转 YOLO，以及已有 YOLO 标签重新分组。
- 类别名称直接读取当前项目数据标注页“管理类别”保存的 `dataset.class_names`，不以当前标注目录扫描结果替代已管理类别。
- “自定义类别名称”映射表左侧行号从 `0` 开始；映射设置仍保存到当前项目设置。
- 预览和执行前均按训练、验证、测试比例划分数据，并在日志中显示类别统计和输出信息。
- 数据处理页面内容区随窗口和全屏后的可用宽度自动扩展，滚动仅用于承载超出高度的内容。

## 模型格式转换

- 数据处理页左侧新增二级工具“模型格式转换”，使用明亮简洁且区别于其他数据处理工具的多格式文件符号并固定在工具列表最下方；支持从 Ultralytics YOLO `.pt` 模型导出 ONNX、TorchScript、OpenVINO、TensorRT 和 NCNN。
- 模型格式转换默认扫描当前项目 `result/**/weights/*.pt`，也允许浏览选择 `data/models/` 或项目外的 `.pt` 文件；基础模型目录不自动出现在转换列表中。
- 页面将源模型和输出目录放在同一行，目标格式、静态方形输入尺寸 `imgsz` 放在下一行；“简化 ONNX”和“安装/替换附加包”放在同一行。附加包安装开始后按钮隐藏，进度条占满该行空隙。默认格式为 ONNX、尺寸为 `640`、简化开启。
- 默认只显示 `result/**/weights/` 下的训练模型，显示名称复用模型验证页规则，例如 `result/train-3/weights/best.pt` 显示为 `train-3/best.pt`；可通过浏览选择其他 `.pt` 文件。默认输出根目录为 `data/models/model_exports/`，每个模型使用独立子目录，产物名分别为 `.onnx`、`.torchscript`、`_openvino_model/`、`.engine` 和 `_ncnn_model/`。
- “预览转换”显示源模型、目标产物、运行环境、能力状态和覆盖风险；目标已存在时必须在执行前确认，只有新产物完整生成后才替换旧结果。
- 转换过程提供结构化实时日志、停止和打开结果文件夹；运行期间禁用模型、格式、参数、环境安装和开始操作，程序退出时复用 `export_handle` 停止子进程。
- ONNX、TorchScript、OpenVINO 和 NCNN 使用基础安装环境。TensorRT 在发布版中需要另行安装模型转换环境包；开发态默认 Pixi 环境直接具备全部能力。
- 模型转换附加包发布名为 `YOLOTool_ExtraEnv_<版本>.7z`，使用 LZMA2 高压缩且只携带 TensorRT 运行库；同时兼容同结构 `.zip`，不执行第三方安装器。用户可通过“安装/替换附加包”选择文件，也可将压缩包拖到模型转换页或系统设置页；已安装旧版本时必须先确认替换。
- 附加包安装在后台显示阶段进度，检查从 5% 开始，解压阶段映射到 5%-95%，之后继续显示完整性校验、TensorRT 探测和原子切换；`.7z` 优先使用基础环境携带的原生 7-Zip CRC 校验，避免解压完成后重复读取所有文件，兼容环境才回退清单 SHA-256。选择阶段只读取压缩包清单并按文件指纹缓存，不枚举正文文件，避免确认和安装重复扫描。
- 主程序先解压到当前安装实例的候选目录，拒绝路径穿越、绝对路径、符号链接、未登记文件、错误平台、协议不匹配和 SHA-256 不匹配；安装器提交后仅比较程序要求的运行时版本与 `_internal` 基础环境清单版本，匹配后才完成安装。安装失败继续使用旧版本，成功后只保留当前版本和一个上一版本，并行安装实例之间不共享活动指针。
- 未安装扩展时选择 TensorRT 会明确提示缺少模型转换环境包；无 NVIDIA GPU 时 OpenVINO 和 NCNN 仍可用，TensorRT 显示硬件不可用。
- 第一版固定 FP32、静态输入、batch 1、无内置 NMS，不开放 FP16、INT8、动态尺寸和校准流程。OpenVINO 不包含 NNCF，TensorRT 不包含 ModelOpt；TensorRT `.engine` 受 GPU、驱动和 TensorRT 版本约束，不保证跨机器通用。

## 其他工具

- 数据处理页同时提供标注预览、批量重命名和图片压缩。
