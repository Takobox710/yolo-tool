# 系统设置规格

## 系统状态

系统设置页显示 Python、Torch/CUDA、Ultralytics、OpenCV、Pillow、ONNX、TensorRT 和程序版本；不单独显示 PySide6，也不在此处显示 GPU、显存、CPU、内存和磁盘状态。依赖版本优先读取发行版元数据，冻结包缺少 `.dist-info` 时回退读取模块自身的 `__version__`，不能只显示“已安装”。

每次程序启动后首次进入系统设置页时，程序在后台请求 GitHub 仓库的最新稳定 Release，并以当前正式程序版本 `1.3.1` 参与版本比较。后续再次切换到该页面不重复检查。检查结果以页面顶部居中的非模态通知显示，通知采用白色圆角卡片、顶部进度条、图标块、阴影和关闭按钮，并在约 4.2 秒后自动收起；网络不可用时只提示暂时无法获取，不阻塞页面和关闭流程。若 Release 版本高于当前程序版本，程序版本卡片后显示透明背景的清晰蓝色圆箭头升级图标，在提示中显示最新版本，并在下方程序日志追加该 Release 的更新内容；点击程序版本号或升级图标均可打开现代化更新窗口，显示当前版本、最新版本、发布说明和下载进度。窗口在进度条上方提供“程序安装包”“基础环境包”“附加环境包”三个选项；环境更新信息模块只在 Release 环境包文件名中的版本高于本机已安装包版本时显示，基础包缺失按首次安装/环境缺失处理；附加包缺失不触发环境更新模块，而显示“当前环境无附加包，可在本界面选择性下载安装”，只有已安装附加包且版本较旧时才触发更新提示；冻结版优先读取安装清单和 `package-info.ini`，源码版回退读取 `installer/*-version.txt`；同版本环境包只保持可选，不会自动提示或勾选。勾选的资源会按顺序下载到用户 `Downloads` 文件夹，勾选程序安装包时下载完成后自动启动安装器；下载期间关闭按钮和窗口 `X` 会被拦截，避免后台下载与界面状态脱离；相同或更低程序版本不显示升级图标，也不追加更新内容，但仍可点击版本号查看窗口。

正式程序版本来自源码内的 `APP_VERSION`；设置页环境卡片和 GitHub Release 检查使用同一正式版本来源。GUI 启动不再因发布清单缺失、环境清单缺失或运行环境版本不一致而强制退出；`--runtime-probe` 仍可用于安装器和诊断流程检查兼容状态，实际缺少运行库时由具体功能显示错误。

## Windows 安装与更新

- 小型 `YOLOTool_Setup_<版本>.exe` 统一负责首次安装、程序升级、修复和确认后的降级，并允许选择新目录并行安装。默认目录为 `YOLOTool`，已有或非空目录不弹额外警告。
- 更新窗口在进度条上方提供“程序安装包”“基础环境包”“附加环境包”三个勾选项；已勾选且 Release 中存在对应资源时，按程序、基础环境、附加环境的顺序下载到当前用户 `Downloads` 文件夹。环境包是否需要更新按 Release 文件名中的包版本与本机安装清单版本比较，而不是按资源是否存在判断。若基础环境包版本更高，程序与基础包默认自动勾选；若没有环境包版本更高，则仅程序包默认勾选；附加环境包始终保持可选。同版本环境包仍可手动选择重新下载。仅程序更新且未勾选环境包时，版本一致提示使用普通灰色文字；手动勾选同版本基础包时，进度条下方显示红色提醒“无需下载，继续下载将重装一次基础环境包”。基础包与程序包一起选择时在进度条下方显示普通说明，基础包被单独留下时显示醒目红字；附加环境包单独下载时按钮显示“下载并安装所选资源”，完成后在程序内复用附加包安装服务进行热安装或替换。勾选程序安装包时下载完成后启动安装器；窗口同时提供访问 GitHub Release 的按钮。
- Release 中缺少对应资源时，相应选项不可用；仅选择基础环境包时提示“仅有基础环境包没有程序无法安装”，不会自动恢复程序勾选，用户确认选择程序后才能开始下载；已有安装但缺少更新基础包时，安装器显示警告并继续使用旧环境，说明部分功能可能受限；首次安装缺少基础包时直接阻止安装，准备好匹配基础包后才能继续；附加环境包单独下载时可在程序内热安装。
- 点击下载前，如果程序和环境包版本都需要更新但只勾选程序，会显示并再次确认更新后的程序可能有部分功能无法使用；如果只有程序需要更新，则显示环境包无需更新并询问是否继续；仅选择附加包且已有附加包时，会提示当前附加包为最新版本并询问是否重新下载替换。
- 安装器启动失败不会让更新窗口保持忙碌状态，下载进度会完成并显示失败原因，用户可以重新尝试；资源下载或安装过程中的窗口关闭请求会被拦截，直到下载 worker 完成。
- 下载按钮右侧提供暂停按钮。下载时可暂停/继续当前资源下载，程序安装器启动后可暂停/继续安装器进程；暂停状态保留当前进度，继续后从当前分块或安装器状态恢复。
- 首次安装、基础环境缺失或版本不兼容时，优先提供匹配的本体环境和模型 `.7z`；首次安装缺少基础包时安装器阻止继续；已有安装缺少新基础包时允许只更新程序、保留旧环境并警告部分功能可能无法使用。基础包安装后的运行环境版本不匹配或自检未通过时也只显示警告并继续安装，不恢复旧版本。
- 模型转换附加环境始终可选。系统设置页支持点击选择或拖入附加包，安装到当前程序目录 `_internal/extensions/model-export-runtime/`；旧版本位于 `%LOCALAPPDATA%/YOLOTool/` 时自动迁移，同盘原子移动，跨盘复制完成后删除旧目录。仅勾选附加包，或同时勾选程序安装包和附加包时，都会根据是否已有附加包分别显示自动安装或下载替换提示；三项全部勾选时会合并显示基础包重装和附加包替换状态；已有附加包时下载前需要确认替换。
- 安装器组件页只快速检查 `YOLOTool_BaseEnv_<版本>.7z` 和 `YOLOTool_ExtraEnv_<版本>.7z` 的名称与大小，点击安装后再执行完整 SHA-256；软件内附加包安装优先由基础包携带的原生 7-Zip 完成并使用 CRC，安装清单隐藏在 `_internal/yolotool_metadata/`。
- 安装成功页在右侧“启动 YOLOTool”选项下方提供“安装完成后删除本次使用的安装包和环境包”，勾选后延迟删除本次使用的安装器、基础环境包和附加环境包。
- 安装开始前由 Inno Setup 的 Windows Restart Manager 注册当前安装目录中的 `YOLOTool.exe`；没有目标进程时直接继续，发现目标进程后由安装器自动关闭，不弹出是否停止应用的询问页，其他安装目录的实例不受影响；自动关闭不负责恢复未保存的程序状态。

安装和更新不覆盖项目设置、最近项目状态、用户模型、图片、标签和训练结果。卸载仅删除受管官方模型，并保留上述用户数据。

## 页面布局与通用设置

- 系统信息区域位于页面最上方，使用白色外框和灰色内卡样式，按四列等宽网格排列并定时刷新。
- 系统设置下方文本区域显示程序日志，不重复承载训练、验证、AI 预标注、数据集划分、模型格式转换和图片压缩页面各自的专属日志。
- 路径设置中，数据集划分、标注预览、批量重命名和数据标注共用图片目录；数据标注、数据集划分和批量重命名共用 Labelme 标注目录；标注预览和数据集划分共用 YOLO 标注目录；图片压缩源目录独立保存。
- 系统信息下方同一行提供 `训练前显示自定义命令框`、`显示配置解释符号`、`模型验证显示 last`、`多类别分布模式` 和 `恢复默认设置`；程序版本卡片在有新版本时显示升级图标。

## 设置文件兼容与维护模型

- 当前项目设置保存于项目目录 `data/runtime/settings.json`，应用级最近项目状态保存于应用根目录 `data/runtime/app_state.json`。
- 设置文件使用 `schema_version: 1`。无版本文件按 v0 迁移，已有字段名、默认值、相对路径存储、外部绝对路径和裸模型名解析规则保持不变。
- 运行时设置由嵌套 `slots=True` dataclass `AppSettings` 表示，页面通过 `WorkbenchContext` 访问 `settings.training.epochs` 等属性，不直接操作任意嵌套字典。
- `SettingsService.load()` 返回设置、迁移标记和问题列表。非法字段只回退该字段，未知字段忽略并报告；损坏 JSON 或需要纠正原文件时先生成一次备份。
- `SettingsService.save()` 只接受 `AppSettings`，保存前再次校验；恢复默认设置保留当前项目根目录。
- 页面设置变更由 `WorkbenchContext.save_settings()` 比较快照后持久化，并只广播实际变化字段；项目切换时递增 generation，使旧页面的后台结果失效。

## 设置项行为

- `训练前显示自定义命令框` 控制训练页是否弹出命令编辑对话框。
- `显示配置解释符号` 只控制字段名后的 `ⓘ` 是否显示；关闭后仍保留字段名称自身的 Qt tooltip。
- `模型验证显示 last` 控制模型验证页是否显示训练结果中的 `last.pt`，默认关闭时只显示 `best.pt`。
- `恢复默认设置` 将当前项目设置恢复到代码默认值，但保留当前项目目录不变。
- 系统设置页不提供常驻的“自动加载 torch”预热开关；Torch/CUDA 环境信息通过短生命周期后台子进程读取，完成后立即退出。环境状态刷新和 GitHub Release 检查属于非阻塞后台任务，关闭程序时不弹出任务确认。
